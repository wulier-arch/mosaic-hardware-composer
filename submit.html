② 创意名称 + 创意介绍

Name · Form · Motivation

创意名称：MOSAIC 拼造（MOSAIC · Hardware Composer）

产品形态：网站。纯静态、零构建，可直接部署到 GitHub Pages / Vercel / Cloudflare。

动机 / 灵感来源：我自己做嵌入式项目时，最常踩的坑不是写代码，而是「买错」—— 3.3V 主控接上 5V 传感器、GPIO 数量不够、I2C 地址撞车，这些错误通常要等收到货、开始接线才暴露， 钱和热情一起浪费。灵感来自马赛克拼图：一套硬件方案本质就是一堆模块的正确拼接， 那为什么不把「这些模块到底能不能拼在一起」这件事，提前到下单之前？

一句话概括：一个在加购瞬间就替你验算电路可行性的硬件选型与下单平台。

③ 目标用户及痛点

Who · When · What problem
  • 创客学生 / 教学场景 —— 手里有板子，但不知道它能接什么。买回来才发现电压不对、 接口不够、例程跑不通，一笔预算就这么打了水漂。
  • 嵌入式 / 硬件工程师 —— 手工核对引脚分配、I2C 地址冲突与功耗预算， 一轮打样前要花两三天做纸面推演；方案改一次，整张核对表就要重来一遍。
  • 硬件初创 / 产品验证 —— 需要 10–100 台样机，但选型、下单、付款、发货散落在不同工具里， 方案无法复用，供应链碎片化，每台都要重新配货跟单。
  • 培训机构 / 实验室采购 —— 要给几十名学生配同一套器材，规格必须完全一致， 还要开发票走报销流程。

这个产品帮用户完成的一件事：在花钱之前，就知道这套方案能不能跑起来。 把「买错」的成本降到零，把方案推演从两三天压缩到几分钟。

④ 功能介绍

How it works · What you get

用户怎么用

  • 浏览 —— 在 8 大分类、86 个模块中按关键词、总线接口、供电电压、价格与库存筛选。
  • 选型 —— 把模块加入工作台，按主控 / 传感器 / 执行器 / 电源 / 通信 / 显示 / 扩展 / 结构 八个分区装配。
  • 校验 —— 每加一个模块，平台实时跑 9 条兼容性规则，并刷新引脚占用、功耗预算、成本明细与难度评分。
  • 下单 —— 校验通过后导出 BOM，填收货信息与发票，创建订单。
  • 支付 —— 微信支付 / 支付宝双通道扫码（已预留服务端下单与回调验签）。
  • 履约 —— 后台确认收款、备货、录入快递单号发货，前台同步物流时间线。

最后得到什么

一份可直接下单的硬件方案：模块清单、BOM 表、资源占用表、功耗预算、成本合计、 难度评分与预计装配工时，全部可以导出为 CSV / JSON。

9 条兼容性校验规则（不是简单的购物车）

  • R0 缺少主控 —— 没有主控时阻断结算，因为主控是全部判断的基准。
  • R1 接口数量超限 —— 逐项比对 UART / I2S / CSI / ADC / PWM 占用；SPI 按每控制器最多 3 个从设备折算。
  • R2 GPIO 引脚不足 —— 累加所有模块占用 IO，并给出「加装 PCF8574 扩展 8 路」的具体建议。
  • R3 逻辑电平不匹配 —— 3.3V 主控 + 5V 器件告警；加了电平转换模块则自动降级为通过。
  • R4 I2C 地址冲突 —— 同地址两个及以上器件告警；加了 TCA9548A 多路复用器则降级为通过。
  • R5 供电能力不足 —— 按峰值电流汇总 5V / 3.3V 轨负载；余量低于 25% 时提醒加大电源。
  • R6 算力档位不足 —— 摄像头与神经网络类模块要求 AI 档，基础算力主控会被直接阻断。
  • R7 缺少必需的总线协议 —— 校验 WiFi / BLE / CAN 能力，例如 CAN 收发模块要求主控内置 CAN 控制器。
  • R8 缺少驱动板或外接电源 —— 含执行器但无驱动板、或所需电源轨无对应电源时告警。

作品特色

  • 规则是真的电气规则，不是营销话术。引擎会读主控的引脚数、总线数、供电能力与算力档位，再逐条比对。
  • 选型热度 —— 7 日 / 30 日双维度指数、环比涨跌、分类聚合与迷你趋势线，并融合本机真实选型行为加权。
  • 全链路打通 —— 选型 → 校验 → 下单 → 支付 → 履约，不是只做前半段。
  • 零构建纯静态 —— 无框架、无打包、无运行时依赖，三平台可直接部署，打开即用。
  • 支付能力已预留 —— 微信支付 V3 Native 与支付宝当面付的签名、回调验签与 Serverless 示例均已就位，替换密钥即可上线。
